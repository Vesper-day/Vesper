# IOS_WIDGET_REBUILD

**Trigger:** The generated iOS project was wiped — typically by `expo prebuild --clean` — or an iOS/Xcode SDK update requires re-adding the native `VesperLiveActivity` widget extension. Native iOS build artifacts under `apps/mobile/ios/` are NOT committed; only the hand-authored extension sources under `apps/mobile/ios/VesperLiveActivity/` are version-controlled and must be re-wired into a freshly generated Xcode project.
**Frequency:** On-demand (after every `expo prebuild --clean`, SDK bump, or native rebuild).
**Owner:** Founder (V1).

> Sibling runbook to `IOS_ALARM_REBUILD.md` (the canonical first prebuild-rebuild runbook). This one covers the Live Activity / Dynamic Island WidgetKit extension authored in chat 077. Like the alarm extension, the device build is **macOS / Xcode only** and additionally gated on Apple Developer enrollment.

> **macOS / Xcode required.** Every step in the Procedure runs on a Mac with Xcode. None of it is runnable on Windows. The chat-077 authoring session committed the sources only; the target was never added to an Xcode project.

## Committed source inventory

These files are committed and are the inputs to this runbook. After `expo prebuild --clean` they are NOT auto-added to the Xcode project — you re-attach them in the steps below.

| File | Role |
|---|---|
| `apps/mobile/ios/VesperLiveActivity/ActivityModels.swift` | **GENERATED** ActivityKit model — `VesperBlockAttributes` + `ContentState` (8 fields). Do not hand-edit; regenerate via `pnpm gen:live-activity-types` |
| `apps/mobile/ios/VesperLiveActivity/VesperLiveActivityBundle.swift` | `@main` WidgetBundle + placeholder `ActivityConfiguration`. Real views/tokens are chat 078 (TODO(078) markers) |
| `apps/mobile/ios/VesperLiveActivity/Info.plist` | Extension Info.plist; `NSExtensionPointIdentifier = com.apple.widgetkit-extension`, bundle id `com.vesper.app.liveactivity`, no principal class (WidgetKit `@main`) |
| `apps/mobile/ios/VesperLiveActivity/VesperLiveActivity.entitlements` | App group `group.com.vesper.app` + keychain `$(AppIdentifierPrefix)com.vesper.app` |

Codegen SSOT (committed, not added to Xcode): `packages/shared/src/liveActivity/schema.json` → emits `ActivityModels.swift` (above) and `packages/shared/src/liveActivity/types.ts`. The two `NSSupportsLiveActivities*` Info.plist keys live on the MAIN app via `apps/mobile/app.config.js`. The main-app app-group + keychain entitlements are likewise in `app.config.js`.

## Detection

This runbook is needed when any of the following is true:
- `apps/mobile/ios/` was just (re)generated by `expo prebuild` / `expo prebuild --clean`.
- A Live Activity push (`apns-push-type: liveactivity`) is accepted by APNs but no activity ever appears on device (target not in the build, or `NSSupportsLiveActivities` missing from the main app).
- The activity starts but never updates the per-minute countdown (`NSSupportsLiveActivitiesFrequentUpdates` missing).

## Required-before-device-build (Cutover gates)

The on-device build and Live Activity test cannot proceed until the following land, all gated on **C-04 (Apple Developer enrollment active)**:

- **C-05 — App ID + App Group.** Register the `com.vesper.app` App ID and the `group.com.vesper.app` App Group in the Developer Portal, with the Live Activities-capable App ID configuration.
- **C-06 — Provisioning profile.** A development/distribution profile that includes the main app and the `com.vesper.app.liveactivity` extension, both with App Groups + Keychain Sharing.
- **C-07 — APNs key.** The `.p8` APNs auth key (`APNS_PRIVATE_KEY` / `APNS_KEY_ID` / `APNS_TEAM_ID`) for the chat-080 `live-activity-pusher` worker to send Push Start/Update/End payloads.

Until C-04 → C-05/C-06/C-07 complete, the widget can be added to the Xcode project and compiled in the simulator, but a real push-driven Live Activity cannot be exercised end-to-end.

## Procedure (DEFERRED TO A MAC SESSION — do not run on Windows)

> Each step below is **Mac/Xcode-only** and is intentionally not executed in the Windows authoring chat. Batch this with the deferred 059b alarm-extension native integration (`IOS_ALARM_REBUILD.md`).

1. **[DEFERRED-TO-MAC] Generate the native project.** From `apps/mobile`, run `expo prebuild` (or `expo prebuild --clean`). This recreates `apps/mobile/ios/` with the main app target only — the widget extension is NOT included.

2. **[DEFERRED-TO-MAC] Add the widget extension target.** Open `ios/Vesper.xcworkspace`. File → New → Target → **Widget Extension**. Name it `VesperLiveActivity`, bundle id `com.vesper.app.liveactivity`, and check **Include Live Activity**. Set the target's **Minimum Deployments** to **iOS 17.2** (match the main app). Delete the template-scaffolded `.swift` files and `Info.plist`.

3. **[DEFERRED-TO-MAC] Wire the committed sources into the target.** Add `ActivityModels.swift` and `VesperLiveActivityBundle.swift` to the `VesperLiveActivity` target. Replace the scaffolded `Info.plist` with the committed one (no principal class — WidgetKit discovers the `@main` `VesperLiveActivityBundle`).

4. **[DEFERRED-TO-MAC] Set app group + keychain on BOTH targets.** On the main app AND `VesperLiveActivity`: Signing & Capabilities → App Groups → add `group.com.vesper.app`; Keychain Sharing → `com.vesper.app`. Point `VesperLiveActivity`'s code-signing entitlements at the committed `VesperLiveActivity.entitlements`. (Requires C-05.)

5. **[DEFERRED-TO-MAC] Confirm the main-app Info.plist keys.** Verify `NSSupportsLiveActivities` and `NSSupportsLiveActivitiesFrequentUpdates` are present on the main app (injected from `app.config.js` by prebuild). Without them activities silently fail at runtime even though the build succeeds.

6. **[DEFERRED-TO-MAC] Build.** Select the Vesper scheme, build for a development device (Xcode Run). Resolve signing prompts. (Requires C-06.)

7. **[DEFERRED-TO-MAC] On-device Live Activity test.** On a **physical iPhone 14 Pro or later** (Dynamic Island hardware), trigger a Push Start via the chat-080 `live-activity-pusher` worker (requires C-07) and confirm: (a) the activity appears in the Dynamic Island / on the lock screen; (b) the per-minute countdown advances locally from `endTime`; (c) an Update payload changes the rendered state; (d) an End payload dismisses it. Non-Pro / pre-14 hardware shows the banner fallback (§7), not the Dynamic Island.

---

## Verification

The rebuild succeeds when:
- A Push Start payload renders a Live Activity in the Dynamic Island (iPhone 14 Pro+) or as a banner (older hardware).
- The countdown advances on-device between server pushes (frequent-updates key working).
- Update and End payloads change and dismiss the activity.
- `git diff --exit-code` is clean after `pnpm gen:live-activity-types` (generated Swift/TS in sync with `schema.json`).

(Full on-device verification is blocked until C-04 → C-05/C-06/C-07 complete.)

## Rollback

If the rebuilt widget misbehaves, remove the `VesperLiveActivity` target from the Xcode project and ship the main app without it: blocks simply do not surface as Live Activities (the app and notifications are unaffected). The committed sources are untouched; re-run this runbook to re-attach.
